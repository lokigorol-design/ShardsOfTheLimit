# Стартовая задача для Codex

Мы начинаем разработку Unity-прототипа тактической игры «Осколки Предела».

Перед любыми изменениями:

1. Прочитай `AGENTS.md` и все файлы в `Docs/Prototype/` полностью.
2. Изучи структуру существующего Unity-проекта и его версию Unity.
3. Проверь текущее состояние Git и не изменяй пользовательские или сторонние файлы без необходимости.
4. Составь короткий план первого этапа. Не проектируй весь финальный продукт заранее.

## Цель первой задачи

Создать минимальный вертикальный технический срез тактического боя:

- фиксированная тестовая сцена с клеточным полем и разными высотами;
- одна управляемая боевая единица;
- выбор клетки и отображение доступного пути;
- перемещение по допустимым клеткам;
- одна способность с раздельными зонами выбора цели и воздействия;
- вторая боевая единица как цель;
- простое нанесение урона;
- минимальный интерфейс состояния и завершения действия;
- возможность запустить сцену из Unity Editor без ручной сборки объектов после каждого запуска.

Используй временную графику: кубы, простые материалы и маркеры. Не создавай отдельную админ-панель. Данные Эхо и способности должны настраиваться через `ScriptableObject` и стандартный Unity Inspector.

## Требования к подходу

- Сначала реализуй минимальную сквозную механику, затем расширяй её.
- Игровая логика не должна зависеть от конкретных моделей, VFX или UI.
- Союзники и враги используют один тип боевой единицы; различается только контроллер.
- Способность состоит из параметров применения, паттерна выбора цели, паттерна области воздействия и списка эффектов.
- Не создавай универсальную систему на все будущие механики. Добавляй только расширения, необходимые текущему этапу.
- Не вводи Тео, Оро и Фау. В прототипе здоровье, щит, инициатива/скорость хода и дальность перемещения задаются напрямую.
- Базовые параметры способности фиксированы и не масштабируются автоматически от характеристик Эхо.

## Ожидаемый результат

По завершении:

1. Рабочая сцена первого этапа.
2. Чистая компиляция без ошибок.
3. Автоматические тесты для чистой логики сетки, дальности/паттерна и урона там, где это практично.
4. Краткий список созданных файлов и архитектурных решений.
5. Инструкция для человека: как открыть сцену, запустить её и проверить результат.
6. Список известных ограничений и следующий минимальный шаг.

Если проект пуст или требуемая версия Unity не указана, сначала зафиксируй обнаруженное состояние и предложи безопасный минимальный вариант, не устанавливая пакеты и не меняя версию Unity без согласования.
