# Стартовый пакет разработки «Осколки Предела»

Этот каталог предназначен для запуска отдельной задачи Codex в папке нового Unity-проекта. Он переводит дизайн-документ и последующие решения обсуждения в конкретные требования к первому тактическому прототипу.

## Что является источником истины

При конфликте документов использовать такой порядок:

1. `PROJECT_RULES.md` — ограничения работы и технические правила.
2. `DECISIONS.md` — уже принятые продуктовые решения.
3. `REQUIREMENTS.md` — границы и требования прототипа.
4. `ARCHITECTURE.md` — целевая архитектура первой версии.
5. `ROADMAP.md` — последовательность реализации.
6. Актуальный дизайн-документ — контекст мира и долгосрочного замысла.

Дизайн-документ версии 1.1 содержит устаревшие для прототипа положения: ранний приоритет HTML-прототипов, расчёт параметров через Тео/Оро/Фау и изменение набора способностей по стадиям. Для текущей разработки они заменены решениями из `DECISIONS.md`.

## Состав пакета

- `START_PROMPT.md` — текст первой задачи для Codex.
- `PROJECT_RULES.md` — готовый файл правил; его можно переименовать в `AGENTS.md` в корне Unity-проекта.
- `DECISIONS.md` — журнал утверждённых решений и отложенных вопросов.
- `REQUIREMENTS.md` — требования к проверяемому боевому прототипу.
- `ARCHITECTURE.md` — данные, игровые подсистемы и границы классов.
- `ROADMAP.md` — этапы с критериями выхода.
- `ACCEPTANCE_TESTS.md` — функциональная и пользовательская проверка.
- `CONTENT_SCHEMA.md` — поля Эхо, способностей, эффектов и ИИ-профилей.
- `DESIGN_DOC_CHANGES.md` — пункты дизайн-документа, которые следует обновить.

## Как запустить работу

1. Создать пустой Unity-проект с контролем версий.
2. Скопировать эти файлы в каталог `Docs/Prototype/` нового проекта.
3. Скопировать `PROJECT_RULES.md` в корень проекта под именем `AGENTS.md`.
4. При желании добавить актуальный дизайн-документ в `Docs/Design/` как справочный материал.
5. Открыть каталог Unity-проекта в Codex.
6. Отправить содержимое `START_PROMPT.md` как первую задачу.
7. Не просить сразу реализовать весь прототип: первая задача должна завершиться аудитом проекта и вертикальным техническим срезом из этапа 1.

## Принцип разработки

Каждый этап подтверждает одну гипотезу и завершается работающей сценой, проверками и краткой документацией. Красивые модели, собственная админ-панель, редактор VFX и универсальный визуальный язык сценариев не входят в первую версию.
