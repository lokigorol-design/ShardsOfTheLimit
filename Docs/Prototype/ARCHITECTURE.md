# Архитектурные заметки

## Непрерывное время боя

`TimelineCoordinator` является единым чистым источником порядка для исполнения и UI. Он хранит глобальный
tick и будущие активации, применяет запланированные импульсы статусов до следующей активации и выдаёт
`GetUpcomingEvents` для прогноза без мутации. MonoBehaviour только отображает события и presentation-корутины.

`CombatUnit.ActivationCount` — runtime-счётчик владельца. Перезарядка хранится как номер активации готовности,
поэтому чужие активации и status ticks на неё не влияют. `BurningState` хранит урон импульса, следующий tick
и tick окончания; ScriptableObject содержит только авторские процент и длительность.

## 1. Слои

### Definitions

Неизменяемые авторские данные: `UnitDefinition`, `AbilityDefinition`, паттерны, эффекты, статусы, AI-профили, визуальные ссылки. Реализуются как `ScriptableObject`.

### Domain/Runtime

Состояние текущего боя и чистые правила: сетка, клетки, путь, доступные цели, очередь, здоровье, щит, перезарядки, выполнение эффектов. По возможности обычные C#-классы без зависимости от сцены.

### Presentation

MonoBehaviour, prefab, камера, подсветка, анимация перемещения, VFX, звук и UI. Слой отображает решения Domain и передаёт намерения пользователя, но не определяет законность действия.

Авторская FBX-модель подключается как presentation-ссылка `UnitDefinition`. Контроллер создаёт
отдельный runtime-root, выравнивает renderer bounds относительно поверхности клетки и добавляет
только collider выбора; это позволяет моделям иметь нормальный pivot на уровне земли и не менять
Domain-координаты или математику перемещения.

### Input/Controllers

Контроллер игрока и ИИ формируют одинаковые команды: выбрать действие, путь, цель и подтвердить. Это позволит заменить мышь на touch и не создавать отдельную боевую логику для врагов.

## 2. Предлагаемые сущности

```text
UnitDefinition (ScriptableObject)
├── identity and presentation
├── base stats
└── AbilityDefinition[]

AbilityDefinition (ScriptableObject)
├── action cost / cooldown
├── TargetingPattern
├── ImpactPattern
├── AbilityEffect[]
└── presentation references

CombatUnit (runtime)
├── UnitDefinition reference
├── team / controller
├── current cell
├── current health / shield
├── cooldowns
└── statuses

BattleState
├── GridState
├── CombatUnit[]
├── TurnTimeline
└── objective state
```

## 3. Команда способности

Рекомендуемый поток:

```text
Input/AI intent
→ запрос допустимых целей
→ выбор цели
→ построение preview области
→ валидация AbilityCommand
→ выполнение эффектов в установленном порядке
→ события результата
→ обновление presentation
```

Preview и фактическое выполнение должны использовать одну математику паттернов, иначе UI будет обещать один результат, а бой применять другой.

## 4. Паттерны

Интерфейс или абстрактный тип паттерна должен получать состояние сетки, источник, ориентацию и выбранную точку и возвращать набор координат. На первом этапе достаточно:

- одиночной клетки;
- радиуса/ромба по манхэттенскому расстоянию;
- линии;
- конуса, только если он необходим первому контенту.

Сложные пользовательские маски и редактор рисования масок отложены.

## 5. Эффекты

Эффект получает контекст способности и формирует/применяет результат. Начинать с `DamageEffect`. Далее по фактической потребности: `HealEffect`, `GrantShieldEffect`, `ApplyStatusEffect`, `PushEffect`, `CreateSurfaceEffect`, `SpawnUnitEffect`.

Необходимо заранее определить порядок эффектов. Например: урон → проверка попадания по здоровью → статус кровотечения. Условные цепочки не следует добавлять, пока конкретная способность не требует их.

Первый реализованный статус — поджог. `ApplyBurnEffectDefinition` хранит только неизменяемый процент
и длительность, `BurningState` живёт в `CombatUnit`, а чистый `BurningCalculator` формирует результаты
наложения и тика. `AbilityRuntime` ведёт отдельное прогнозное состояние статуса, поэтому Preview не
меняет бой и совпадает с Execute; `TimelineCoordinator` передаёт результаты глобальных импульсов Presentation-слою.

## 6. Сетка и высота

Логические координаты не должны вычисляться каждый раз из мировых координат Transform. Сцена служит авторским представлением карты, а при запуске создаёт проверенную логическую сетку. Правила соседства, стоимости шага и допустимого перепада высоты находятся в Domain.

## 7. Таймлайн

Подтверждён непрерывный событийный timeline без раундов. `TimelineCoordinator.GetUpcomingEvents` является
единым источником порядка для исполнения и UI; прогноз не изменяет состояние боя.
Чистые `BattleReadabilityRules` определяют исход боя и однозначные буквенные коды намерений.
Выбор конкретной способности остаётся в контроллере AI, а Presentation раскрывает только два
слота ближайшего противника.

## 9. Главные риски

- Слишком ранняя универсализация редактора способностей.
- Смешивание ассетов-определений с изменяемым состоянием боя.
- Дублирование классов союзников и врагов.
- Несовпадение preview и реальной области способности.
- Жёсткая связь правил боя с MonoBehaviour и UI.
- Попытка решить мобильное управление после построения интерфейса только под мышь.
- Добавление сложной высоты и линии видимости до проверки базового темпа боя.
